# Agent Creation Standard

## Centralized creation

Only the Manager may create, assign, redirect, replace, or retire subagents in v1.

Workers may report that another specialty is required. They may not spawn it.

## One agent, one lane

Every worker must have:

- one specialist role;
- one clear objective;
- one inspectable deliverable or tightly cohesive deliverable set;
- explicit required inputs;
- explicit constraints;
- explicit allowed tools;
- acceptance criteria defined before work begins;
- a stop condition.

Avoid generic worker roles such as "handle marketing" or "build the product." Prefer lanes such as "produce a competitor comparison dataset" or "implement the approved responsive pricing section."

## Context policy

Provide minimum sufficient context. Do not dump the whole project into every worker.

A task packet should include only:

- relevant goal context;
- accepted upstream artifacts;
- constraints that affect the lane;
- interfaces/dependencies;
- required source or tool access;
- acceptance criteria.

## Worker autonomy

Within the lane, workers may choose methods, sequencing, implementation details, and permitted tools. They may not broaden scope, change the goal, create workers, or make external commitments.

## Agent archetypes

Roles are dynamically generated, but common archetypes include:

- researcher;
- domain expert;
- analyst;
- implementer;
- designer;
- writer;
- tester;
- reviewer;
- adjudicator;
- domain-scoping expert.

Archetypes are starting points, not a permanent roster.

## Lifetime

Workers are temporary by default. Reuse only for a continuing specialist lane where continuity provides real value.
